**RDI-08 — equally supported causes are inconclusive**

- `DeterministicPlannerService` now reports `TiedCandidates` (all retrieval matches sharing the selected
  playbook's top score). Selection is unchanged, so the August planner and its lexical-tie golden keep
  their behavior.
- The diagnostics workflow records tied candidates in `diagnostics.plan` and executes **no** tool for an
  ambiguous plan. The rule critic returns `inconclusive / evidence.ambiguous` before the optional model
  critic is consulted, so a model cannot approve an ambiguous diagnosis.
- The outcome names the competing playbooks in `narrowingCandidates` so the caller can narrow the request.
- `ValidateCritic` rejects any recorded/replayed acceptance or executed step on a plan with tied candidates.
- Case: terms `configuration` + `pricing` tie `configuration-trace` and `pricing-diagnosis`. Before this
  change the request would have been diagnosed confidently as a configuration issue.
- Boundary: ambiguity is detected at retrieval (equal support for competing causes in the request), not by
  executing both candidate plans and comparing grounded evidence.

**RDI-11 — network-requiring step is denied before execution**

- `RepositoryTestProfile` has an operator-declared `RequiresNetwork` flag. The repository tool denies such
  profiles with stable code `repo.network.denied` before the test runner starts, on every executor backend.
- Added catalogued profile `pricing.live-rates` (a pricing integration suite that fetches live exchange
  rates). Its packaged worker body exists; if policy were bypassed, the hardened container's disabled
  network makes it fail rather than reach the network.
- The pricing playbook's search/read steps succeed; the test step is denied; the critic returns
  `policy.denied`; recovery stops (a policy denial is never retried around).

**RDI-12 — replay after the snapshot is removed**

- Cases can set `replayWithoutSnapshot`. The evaluation runner copies the snapshot to a disposable staging
  directory, verifies its content hash against the request, executes the case against that copy, disposes
  the sandbox pool, deletes the copy, and only then replays. The report records
  `snapshotRemovedBeforeReplay`; the gate fails if it is false.
- A unit test performs the same sequence in-process through the replay CLI.

**Evaluation plumbing**

- Cases may declare `expectedDenialCode`; the prohibited-action metric now checks it instead of hard-coding
  RDI-09/RDI-10 (`repo.path.denied`, `planner.plan.invalid`, `repo.network.denied`).
- New contract fields (`tiedCandidates`, `narrowingCandidates`) are omitted when null, keeping September
  signed events and artifacts byte-compatible. Plan/playbook/diagnostics schemas remain `0.1`;
  manifest `0.3`; event log `0.2`.
