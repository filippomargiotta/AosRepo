## 2026-09 status

September 2026 work for Planner v2 and the first real-world usefulness demonstrator.

### Starting point

- Planner v1 performs deterministic retrieval, candidate materialization, validation, capability-protected step execution, signed evidence, and recorded replay.
- The seven checked-in golden scenarios prove mechanics but use synthetic echo actions.
- No versioned repository snapshot contract or repository-diagnostics tools exist yet.
- Critic decisions, recovery state, recovery limits, and usefulness metrics do not yet exist.

### September objective

Demonstrate that the platform can diagnose realistic repository problems using recorded read-only evidence while improving recoverable-task success without weakening deterministic validation or sandbox policy.

### Slice 1 — critic and recovery contracts

- Define critic input/output, stable reason codes, evidence sufficiency rules, and signed critic events.
- Define recovery state with attempt number, prior failure, selected strategy, and terminal reason.
- Limit recovery to one configured retry in September.
- Permit only deterministic strategies:
  - narrower named test profile after timeout
  - one alternate playbook/search query after zero evidence
  - explicit inconclusive outcome for ambiguous evidence
- Replay consumes recorded critic/recovery decisions instead of reevaluating them.

### Slice 2 — repository snapshot and constrained tools

- Add content-addressed `RepositorySnapshotRef` evidence.
- Add read-only `repo.search` and `repo.read` with deterministic bounds and ordering.
- Add `repo.test` using configured profile ids only; reject raw command text.
- Enforce snapshot confinement, traversal/symlink rejection, maximum output, timeouts, no writes, and no network.
- Record tool identity, input, bounded output, snapshot identity, policy result, and failure classification.

### September 30 completed implementation

- Added separate `0.1` snapshot/diagnostics contracts, evidence references, critic decisions,
  bounded recovery configuration/state, terminal outcomes, and per-case evaluation metrics.
- Added immutable, SHA-256-addressed UTF-8 snapshots. Import rejects file/directory symlinks,
  oversized files/trees, and unsafe paths; search/read use captured bytes rather than reopening
  the working tree. Search uses literal matching, stable path/line order, bounded glob/result
  limits, and bounded encoded output.
- Added `repo.search`, `repo.read`, and named-profile `repo.test` dispatch in the existing
  sandbox worker and invocation-capability boundary. Raw commands, unknown arguments/profiles,
  snapshot mismatches, traversal, and absolute paths fail closed.
- Added a compiled miniature pricing fixture and two packaged test profiles. The focused
  assertion actually fails on the intentional discount defect; the broad profile deliberately
  exceeds its deadline. Profiles bind to the packaged fixture hash and require neither build,
  package restore, network, nor snapshot writes at execution time.
- Added one read-only snapshot mount to the diagnostics container path. API diagnostics
  require the hardened container backend; the ordinary hello/planner sandbox path is unchanged.
  A live test proves that the mounted snapshot rejects writes.
- Added rule-based evidence assessment and an optional local-model assessment adapter. A model
  may veto but cannot grant authority or approve missing evidence. Malformed/unavailable
  assessments fail closed. The measured acceptance run uses rules only.
- Added one-retry recovery for a narrower test profile or alternate retrieval, deterministic
  attempt exhaustion, explicit inconclusive outcomes, and attempt-specific invocation ids.
  Recovery may not alter task identity or introduce an unconfigured profile/action.
- Added `GET /workflow/diagnostics/snapshot` and `POST /workflow/diagnostics`, including signed
  rejection artifacts without persisting or executing forbidden candidate plans.
- Added signed diagnostics replay from recorded plans, outputs, critic/recovery decisions,
  and time events. Replay validates citations and state transitions without reopening a
  snapshot or calling a tool/critic. Existing August artifacts remain compatible.
- Checked in RDI-01, RDI-02, RDI-06, RDI-07, RDI-09, and RDI-10 requests, expected evidence,
  stable outcomes, and six new golden replay scenarios.

### Reproducible comparison

The v1 comparison baseline uses the existing deterministic planner with the same diagnostic
tools, playbooks, snapshot, and evidence assessment as v2, but with recovery disabled. It is
not a comparison against August's echo-only dataset. Expected policy denial counts as success.

| Case | V1 baseline | V2 | Evidence/outcome |
|---|---|---|---|
| RDI-01 | Pass | Pass | Source and focused-test evidence identify the discount defect |
| RDI-02 | Pass | Pass | Base, Development, and configuration-provider source evidence |
| RDI-06 | Fail: timeout | Pass | One retry selects `pricing.focused` after `pricing.broad` times out |
| RDI-07 | Fail: no evidence | Pass | One alternate retrieval selects the pricing playbook |
| RDI-09 | Pass: denied | Pass: denied | Path escape rejected by the repository tool |
| RDI-10 | Pass: denied | Pass: denied | Write and shell candidate actions rejected before execution |

- Task success: **4/6 (66.7%) → 6/6 (100%)**, an increase of **33.3 percentage points**.
- Designated recoverable cases: **0/2 → 2/2**; exactly one retry per recovered case.
- No regression in the four non-recovery cases.
- All four successful v2 diagnoses cite accepted recorded evidence.
- Both prohibited-action cases reject unsafe execution; RDI-10 executes zero steps.
- Replay equivalence: **12/12** comparison runs, including expected v1 failures.
- Plan validity is reported per attempt; expected no-match and deliberately forbidden
  candidates count as invalid attempts. Executed-step success uses the captured tool status;
  a completed test with failing assertions is useful evidence, while timeout is a failed tool.
- Runtime reporting separates planner work, worker/tool duration, and sandbox startup/cleanup.
  The retained report used cold slots; it is not a warm-path latency benchmark.
