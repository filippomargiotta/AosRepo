## 2026-06 status

Initial June 2026 work for secure sandbox v1.

2026-06 starting point
- May router v2 is closed with metrics-weighted deterministic routing and benchmark evidence.
- Replay artifacts currently use manifest schema `0.3` and event-log schema `0.2`.
- Tools were previously only manifest references; no workflow invoked a tool or captured tool I/O yet.

2026-06 update (1/3 DONE)
Implemented the tool execution protocol v1:
- Added core tool execution contracts:
  - `ToolExecutionRequest`
  - `ToolExecutionResult`
  - `ToolExecutionEvent`
  - `IToolExecutor`
- Added `DeterministicEchoToolExecutor` as the first deterministic executor.
- Integrated tool execution into the `hello` workflow.
- The workflow now emits two HMAC-chained event-log records:
  - `tool.execution` with invocation id, tool id/version, status, input JSON, output JSON, and error
  - `workflow.hello` with the workflow result and referenced tool invocation/output
- Replay now feeds manifest start time plus event timestamps back into the workflow.
- Golden artifacts were refreshed so the checked-in replay scenario includes captured tool I/O.
- Added test coverage for:
  - tool execution event capture
  - deterministic manifest/event-log summary update
  - changed tool output changing captured event-log MACs
  - replay CLI compatibility with the two-event golden artifact

2026-06 update (2/3 DONE)
Implemented JWT capability-token enforcement around tool execution:
- Added deterministic HS256 JWT issuance and validation with:
  - issuer, audience, key id, token id, issued-at, and expiry claims
  - exact run id, invocation id, tool id/version, and action binding
  - stable allow/deny reason codes
- Extended tool requests with the capability scope, token, and recorded request time.
- Added `CapabilityEnforcingToolExecutor` in front of the deterministic executor.
- Denied requests never reach the underlying executor and return a deterministic `denied` result.
- Raw JWTs are stripped before delegation and are never written to manifests or event logs.
- Signed artifacts now record the capability policy decision and non-secret token id.
- Replay reissues a deterministic capability using recorded workflow time and reproduces the same signed decision.
- Added test coverage for:
  - successful authorization and token stripping
  - expiry and invalid signature
  - run, invocation, tool, version, and action mismatches
  - denied execution without delegate invocation
  - signed allow/deny audit artifacts
  - raw-token exclusion from artifacts
  - golden replay stability

2026-06 notes
- The 1/3 protocol slice intentionally landed before JWT capability enforcement.
- This intentionally does not add a real gVisor/Firecracker/pre-warmed isolation pool yet.
- Tool protocol came first so JWT enforcement and sandbox execution can attach to a stable contract.
- Manifest schema remains `0.3`; event-log schema remains `0.2` because the signed event-log envelope did not change. The new tool I/O is a domain event payload.

2026-06 remaining plan
- 3/3: pre-warmed isolation pool behind `IToolExecutor`, preserving the same tool protocol, capability gateway, and replay surface.

2026-06 definition of done progress
- A workflow can call a deterministic tool and capture all I/O in signed replay artifacts. (DONE for protocol v1)
- A workflow can call an actually sandboxed/pre-warmed tool. (PENDING)
- Capability-token enforcement protects tool execution. (DONE)

2026-06 scope boundary
- Capability enforcement is at the tool-execution gateway, where run/invocation/tool claims can be checked immediately before use.
- External identity-provider integration, JWKS/key rotation, and general API-user authentication are not part of this capability slice.
- The actual sandbox and pre-warmed pool remain the final June 3/3 chunk.
