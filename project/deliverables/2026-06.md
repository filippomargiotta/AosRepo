## 2026-06 status

Initial June 2026 work for secure sandbox v1.

2026-06 starting point
- May router v2 is closed with metrics-weighted deterministic routing and benchmark evidence.
- Replay artifacts currently use manifest schema `0.3` and event-log schema `0.2`.
- Tools were previously only manifest references; no workflow invoked a tool or captured tool I/O yet.

2026-06 update (1/3 DONE)
Implemented the tool execution protocol v1:
- Added core tool execution contracts:
  - `ToolExecutionRequest`
  - `ToolExecutionResult`
  - `ToolExecutionEvent`
  - `IToolExecutor`
- Added `DeterministicEchoToolExecutor` as the first deterministic executor.
- Integrated tool execution into the `hello` workflow.
- The workflow now emits two HMAC-chained event-log records:
  - `tool.execution` with invocation id, tool id/version, status, input JSON, output JSON, and error
  - `workflow.hello` with the workflow result and referenced tool invocation/output
- Replay now feeds manifest start time plus event timestamps back into the workflow.
- Golden artifacts were refreshed so the checked-in replay scenario includes captured tool I/O.
- Added test coverage for:
  - tool execution event capture
  - deterministic manifest/event-log summary update
  - changed tool output changing captured event-log MACs
  - replay CLI compatibility with the two-event golden artifact

2026-06 notes
- This intentionally does not add JWT capability enforcement yet.
- This intentionally does not add a real gVisor/Firecracker/pre-warmed isolation pool yet.
- Tool protocol came first so JWT enforcement and sandbox execution can attach to a stable contract.
- Manifest schema remains `0.3`; event-log schema remains `0.2` because the signed event-log envelope did not change. The new tool I/O is a domain event payload.
