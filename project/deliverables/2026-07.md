2026-07 update (1/3 DONE)
Implemented the first process-backed sandbox slice:
- Replaced `InProcessSandboxSlot` with `ProcessSandboxSlot`.
- Added `Aos.SandboxWorker`, a single-use console worker process:
  - parent starts the worker and waits for a deterministic ready line
  - parent sends one `ToolExecutionRequest` JSON line over stdin
  - worker returns one `ToolExecutionResult` JSON line over stdout
  - release disposes the used process and schedules a fresh worker refill
- Preserved `PreWarmedSandboxPool` one-shot semantics:
  - warm acquire dequeues an already-started worker process
  - cold acquire starts a new worker process
  - release disposes the used process and refills up to configured pool size in the background
- Left `PooledSandboxToolExecutor` as the same measuring wrapper, now backed by process slots.
- Updated `SandboxPoolOptions.ExecutorType` and benchmark output to `process-v1`.
- Added deterministic sandbox failure surfaces:
  - worker crash -> `status: failed`, `error: sandbox_process_exit`
  - worker timeout -> `status: failed`, `error: sandbox_timeout`
  - malformed worker response -> `status: failed`, `error: sandbox_protocol_error`
- Kept sandbox execution metadata runtime-only. Signed manifest/event-log schema remains unchanged.

2026-07 update (1/3 review fixes)
Addressed the first review findings before treating the slice as stable:
- `PreWarmedSandboxPool.Release()` no longer synchronously starts the replacement worker before returning.
- Pool refill now runs in the background and tracks in-flight refills so warm-path caller latency does not hide process startup cost.
- Pool dispose/release coordination now uses a lock; late-created replacement workers are disposed instead of queued after pool disposal.
- Worker crash/timeout test commands are gated behind `AOS_SANDBOX_WORKER_TEST_COMMANDS=1` and are disabled in the default worker process.
- Worker stderr is drained asynchronously so a noisy worker cannot block on a full redirected stderr pipe.
- README benchmark examples now use bounded process-v1 iteration counts.

Tests added/updated:
- process worker executes the deterministic echo tool through a subprocess
- disposed process slots reject reuse
- worker crash returns stable `sandbox_process_exit`
- worker timeout returns stable `sandbox_timeout`
- worker test commands are ignored unless explicitly enabled for tests
- worker stderr is drained without deadlocking execution
- `Release()` schedules replacement without blocking caller latency
- dispose during pending refill does not keep a replacement queued
- pool release refills with a fresh process id
- existing warm/cold, concurrency, capability-gateway, and benchmark coverage now runs through process-backed slots

2026-07 update (2/3 DONE)
Implemented the hardened container isolation backend and security suite:
- Added `ISandboxSlot` plus `SandboxSlotFactory`, so the existing pool can host multiple isolation backends without changing pool semantics.
- Retained `process-v1` for fast protocol/unit coverage and added `container-v1` as the Web API default.
- The Web API now materializes the pool before accepting traffic, so container startup is not deferred into the first workflow request.
- Added a pinned multi-stage worker image in `source/Aos.SandboxWorker/Dockerfile`.
- `container-v1` runs each one-shot worker with:
  - isolated network namespace with networking disabled
  - read-only root filesystem and bounded writable `/tmp` tmpfs
  - non-root uid `1654`
  - all Linux capabilities dropped
  - `no-new-privileges`
  - `192 MB` memory, `0.5` CPU, and `32` PID limits
  - no host bind mounts and an explicit container environment
- Tightened both process and container protocols so a worker response must match the request invocation, tool identity/version, and input.
- Added opt-in OrbStack/Docker integration coverage for:
  - successful isolated tool execution
  - effective OCI/Docker resource and security configuration
  - denied root-filesystem writes
  - denied outbound networking
  - host environment secret exclusion
  - concurrent tenant containers not sharing tmpfs state
  - deterministic memory-limit and timeout failures
  - timeout cleanup leaving no container behind

2026-07 technical conclusion
- The pre-warmed hardened path meets the `<50 ms` overhead hypothesis at p95 on the measured host (`26.6897 ms`).
- Cold container startup does not meet the target (`225.1958 ms` total p95), validating that pre-warming is required.
- The delivered backend uses OrbStack's OCI `runc` runtime with namespaces, cgroups, seccomp support, and explicit hardening flags. It is not gVisor/Firecracker; `ISandboxSlot` keeps a future `runsc` or micro-VM backend isolated from pool and workflow code.
- July's Definition of Done is satisfied: the security suite is documented and executable, overhead is measured, and signed replay includes sandbox outcomes.
